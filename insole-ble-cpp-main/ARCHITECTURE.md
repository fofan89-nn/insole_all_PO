# Архитектура TCP сервера для BLE стелек

## Общая схема

```
┌─────────────────────────────────────────────────────┐
│  BLE Адаптер (Bluetooth Low Energy)                 │
│  Сканирует и находит две стельки (левую и правую)  │
└────────────────┬────────────────────────────────────┘
                 │
                 ├──────────────────────┬──────────────────────┐
                 │                      │                      │
        ┌────────▼────────┐    ┌────────▼────────┐    ┌────────▼────────┐
        │  Правая стелька │    │  Левая стелька  │    │  Адаптер        │
        │  (INSOLE_RIGHT) │    │  (INSOLE_LEFT)  │    │  (сканирование) │
        └────────┬────────┘    └────────┬────────┘    └─────────────────┘
                 │                      │
                 │                      │
        ┌────────▼────────────┬─────────▼────────────┐
        │   TCP Server #1     │   TCP Server #2      │
        │   Port: 8001        │   Port: 8002         │
        │   (INSOLE_RIGHT)    │   (INSOLE_LEFT)      │
        └────────┬────────────┴─────────┬────────────┘
                 │                      │
        ┌────────▼──────────┐  ┌────────▼──────────┐
        │  Client 1         │  │  Client 1         │
        │  Client 2         │  │  Client 2         │
        │  Client N         │  │  Client N         │
        └───────────────────┘  └───────────────────┘
```

## Компоненты

### 1. TcpServer (структура)

Управляет TCP сервером для одной стельки.

**Члены:**
- `SOCKET listen_socket` - слушающий сокет
- `std::vector<SOCKET> client_sockets` - список подключенных клиентов
- `std::mutex clients_mutex` - синхронизация доступа к списку клиентов
- `std::atomic<bool> running` - флаг работы

**Методы:**
- `bool init(int port)` - инициализация сервера на порту
  - Создает сокет
  - Настраивает опцию SO_REUSEADDR
  - Привязывает к портству
  - Слушает входящие соединения
  
- `void accept_clients()` - бесконечный цикл приема клиентов
  - Вызывается в отдельном потоке
  - Принимает входящие соединения
  - Добавляет сокеты клиентов в список
  
- `void send_data(const SensorData& data)` - отправка данных всем клиентам
  - Упаковывает данные в бинарный формат (18 байт)
  - Отправляет всем подключенным клиентам
  - Удаляет отключившихся клиентов
  
- `void close_socket()` - корректное завершение
  - Закрывает прослушивающий сокет
  - Закрывает все сокеты клиентов
  - Очищает список клиентов

### 2. SensorData (структура)

```cpp
struct SensorData {
    uint64_t timestamp;      // 8 байт - временная метка (мс)
    int16_t values[8];       // 16 байт - 8 значений сенсоров
};
// Всего: 24 байта в памяти, 18 байт в сетевом пакете
```

Примечание: В сетевом пакете размер 18 байт (timestamp 5 байт передается в исходном коде, но в структуре uint64_t).

### 3. Основной поток (main())

1. **Парсинг параметров**
   - `--scan-duration=MS` (по умолчанию 5000)
   - `--right-port=PORT` (по умолчанию 8001)
   - `--left-port=PORT` (по умолчанию 8002)

2. **Инициализация Bluetooth**
   - Проверка включения Bluetooth
   - Получение адаптера
   - Проверка включения адаптера

3. **Инициализация TCP серверов**
   - Создание сервера для правой стельки
   - Создание сервера для левой стельки
   - Запуск потоков приема клиентов

4. **BLE сканирование**
   - Сканирование устройств в течение scan_duration
   - Подключение к найденным стелькам

5. **Основной цикл**
   - Ожидание сигнала выхода (SIGINT, SIGTERM)

6. **Корректное завершение**
   - Отключение от всех BLE устройств
   - Закрытие TCP серверов

### 4. Поток приема BLE данных

Для каждой подключенной стельки создается callback на `notify`:

```
BLE уведомление → Parse пакета → Структура SensorData → send_data() → TCP клиентам
```

**Процесс:**
1. Получение пакета BLE (17 байт)
2. Распаковка временной метки (5 байт)
3. Распаковка 8 ADC значений (12 бит каждое)
4. Создание SensorData
5. Отправка через TCP всем подключенным клиентам

## Кроссплатформенность

### Windows vs Linux

```cpp
#ifdef _WIN32
    #include <winsock2.h>
    #include <ws2tcpip.h>
    // Windows специфики:
    // - WSAStartup() / WSACleanup()
    // - closesocket() вместо close()
    // - SD_BOTH вместо SHUT_RDWR

    #include <arpa/inet.h>
    #include <unistd.h>
    #include <netinet/in.h>
    #include <sys/socket.h>
    // Unix специфики:
    // - close() для сокетов
    // - SHUT_RDWR для shutdown
#endif
```

## Синхронизация потоков

### Mutexes

1. **devices_mutex** - защита списка подключенных BLE устройств
   - Используется в: callback отключения, цикл отключения

2. **tcp_servers_mutex** - защита доступа к TCP серверам
   - Используется в: инициализация, отправка данных, завершение

3. **clients_mutex** (внутри TcpServer) - защита списка TCP клиентов
   - Используется в: accept_clients(), send_data()

## Обработка ошибок и исключений

### Обработка сокетов
- Проверка INVALID_SOCKET при создании
- Проверка SOCKET_ERROR при операциях
- Корректное закрытие при ошибке

### Сигналы
- SIGINT (Ctrl+C) - корректное завершение
- SIGTERM - корректное завершение

### Отключение клиентов
- Удаление из списка при ошибке отправки
- Закрытие сокета отключившегося клиента

## Производительность

### Пропускная способность
- Один пакет: 18 байт
- Типичная частота: 100 пакетов/сек = 1800 байт/сек
- Две стельки: 3600 байт/сек

### Потоки
- 1 основной поток (main)
- 2 потока приема TCP клиентов (accept_clients)
- N потоков BLE callbacks
- 1 поток счетчика PPS (опционально)

### Память
- Один TcpServer: ~200+ байт + вектор SOCKET'ов
- Один подключенный клиент: 1 SOCKET (~4-8 байт) + буфер отправки

## Сценарии использования

### 1. Локальное подключение
```
Приложение → localhost:8001 → TCP сервер ← BLE адаптер ← Стелька
```

### 2. Подключение с другого хоста
```
Удаленное приложение → 192.168.1.100:8001 → TCP сервер
```

### 3. Запись в файл
```
Python клиент → файл → Анализ данных
```

### 4. Обработка в реальном времени
```
Несколько клиентов одновременно получают данные
```

## Безопасность

**Текущие ограничения:**
- Нет аутентификации
- Нет шифрования
- TCP слушает на 0.0.0.0 (все интерфейсы)

**Рекомендации для production:**
- Ограничить слушание на localhost или конкретный интерфейс
- Добавить аутентификацию (токены, сертификаты)
- Использовать TLS/SSL для шифрования
- Добавить rate limiting для защиты от DoS
- Валидировать входные параметры
